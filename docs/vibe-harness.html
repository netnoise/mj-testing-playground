Design v4.1 · portable AI harness

Vibe Harness

An agent that runs whole loops unattended, survives being killed mid-flight, comes back having taught you something about your own codebase — and keeps what you point at.

Target mj-testing-playground (Angular 14) Portable to any repo, any agent, any OS Status Phase 0+1 built, verified end to end, and delivered a real feature Shaped by the TriTrack review · Angular 9→14 migration, 2026-09-04
00 — SPINE

Six ideas, everything else follows

Doors

Reversibility decides who's in the loop. Seven one-way actions stop the agent. Everything else runs to completion, because the undo is deleting a branch.

Teeth

A rule the agent must police itself is advisory. The ones that matter are hooks over a single-writer state file. This came from evidence, not caution: in the reviewed repo, every prompt-level constraint eventually lost to gate pressure; its one hook-enforced constraint held.

Digest

The checkpoint pays you in knowledge. An agent reads thirty files to change three. What it learned about your system is the product; the diff is a by-product.

Skills

Self-sufficient, therefore composable. Each heals its own preconditions, so it works alone; each writes to a run directory, so it chains. The filesystem is the bus.

Journal

Nothing valuable lives only in a context window. An append-only line per step means a usage limit or a dead container costs minutes, not the run.

Bank

You point, it keeps. A curated store of facts, failures and hunches that outlives the repo — raw material for reasoning, for writing, and for tuning the process itself.

The lightweight test. You type three words (/fix, /keep, /handoff), you occasionally write one line answering one question, and you own three files: MODEL.md (structure), .ai/bank/ (what you chose to keep), .ai/harness/OWED.md (what you strike once it's applied). Everything else in .ai/ is written by the agent for the agent. If you never open that folder, the workflow still works — that's the standard the boilerplate has to meet.
01 — COUPLING

Doors, not tiers

The only question that should stop an agent is: can this be undone by deleting a branch?

Two-way

→ run the whole loop, report after

  • Any edit on a branch that isn't pushed to a shared ref
  • Adding tests, refactors, renames
  • Reading anything, anywhere
  • New files in an area the brief named
  • Failed experiments — deleting the branch is the undo

One-way

→ stop, and make the stop informative

  • Adding, removing or bumping a dependency
  • Schema or data migration
  • Changing a contract something outside the repo calls
  • Deleting or weakening an existing test
  • Anything under auth, secrets, payments
  • Writing outside the repo; pushing to a shared branch; rewriting history
  • Editing the config that defines a gate's own scope — one owner, .claude/hooks/budget.mjs's GATE_SCOPE, which emits the live list to .ai/harness/gate-scope.json on every invocation rather than being kept as prose in four or five places that can each drift independently (one of them already had)

Seven lines you can hold in your head, versus a tier matrix you'd have to consult. When the agent hits a one-way door it doesn't ask permission — it writes down what the door is, what's on both sides, what it would do by default and what being wrong would cost. Then it carries on with everything that doesn't depend on the answer, and the question waits for you in the digest.

Door 7 is the review's addition, and it's the only always-enforced one. It exists because its symptom is a better number: the reviewed repo shipped a mutation glob narrowed to one file — no test deleted, score still green, coverage of everything else silently gone. No gate can see that, so budget.mjs blocks those edits whether or not a run is active; the deliberate override is HARNESS_DOOR_OPEN=1, named in the digest and logged in the run's own door-crossings.md. Corollary: a gate metric that improves after an agent edited the gate's config is not evidence.

The override has a platform dependency worth naming. It works when the agent's own process can reach an environment where that variable is set — a terminal session. It does not work in the Claude Code desktop app: there is no exposed terminal the hook-runner process reads its environment from, confirmed by trying twice, including once immediately after the human exported it in a separate terminal window. In that environment, every door-7 change becomes a prepared patch file the human applies directly — slower, but no less sanctioned; the disclosure still happens, it just happens as a diff handed over rather than an env var set.

Cost travels with the door. A two-way door is free to walk through in risk terms but not in spend, so every run carries a budget and reports at the halfway mark — one line, no action needed. That's what lets you kill a run that's wandering before it burns the rest of its allowance, without watching it.

The four sections that earn the read

One decision for you. Singular, with a default, a cost, and a reversibility note. Zero decisions is the common case — and then nothing interrupts you at all. This is the mechanism that converts approvals into reading.

What surprised me. Where the code contradicted a reasonable expectation. That's where brownfield tacit knowledge lives — what a fresh reader notices and a veteran has stopped seeing. It's also the honest signal that the code was read rather than pattern-matched.

What I learned about your system. Three cited findings you didn't ask for, free from work already done.

Concept. The transferable idea, named, plus a grep for the next place it applies. You stop learning this bug and start learning the class, anchored to an instance in your own code.

Nothing here can be rubber-stamped, because there's usually nothing to stamp. The risk inverts from you not reading to the agent writing filler — and that's now a script, not a habit: check-citations.sh resolves every file:line in a digest, brief or record. Its very first run caught three miscited lines in the brief that produced it — which taught the boundary precisely: it proves a citation resolves, not that it's apt, so it prints each cited line's content for the human eye to catch the misattributions.

And one state can never be dressed as done: unverified_at_runtime. A run whose gates were all static says so, loudly, in the digest and the handoff. Green is not running — the reviewed repo paid three full debugging cycles for a component that passed typecheck, lint and build and crashed the first time a browser opened it.

03 — AUTONOMY

Budgets with teeth

Unbounded autonomy is what makes people reach for approval gates. Bound it explicitly — and enforce the bound mechanically, because a budget the agent polices itself has already been shown to lose under gate pressure.

# .ai/prompts/implement.md — frontmatter DECLARES the contract;
# .claude/hooks/budget.mjs ENFORCES it, over .ai/run/<slug>/state.json
needs:    understand              # auto-runs it if brief.md is absent
model:    large                   # small | large — see §07
reads:    .ai/run/*/brief.md, src/**
writes:   src/**, .ai/run/*/implement.json
budget:   45m · 12 files
stop_on:
  - enforced: one_way_door           # door 7 blocks always, run or no run
  - enforced: blast_radius_exceeded  # against the brief's allowed_paths
  - enforced: budget_spent           # files touched + wall clock
  - advisory: hypothesis_falsified   # only the agent can notice this
  - advisory: runtime_falsified      # green gates, crashed when executed
on_stop:  write handoff, leave branch, exit clean

The enforced/advisory tag is the honest line. Enforced entries are checked by a PreToolUse hook before every edit: it is the sole writer of state.json (files touched, wall clock, the brief's path allowlist), so the budget's book-keeping can't drift, and blast radius stops being a judgment call — /understand writes the allowlist, the hook does path checks. Advisory entries are labelled as such so nobody mistakes an instruction for a mechanism. The hook fails open on anything unexpected: a guard that blocks every edit on a schema change is worse than no guard.

hypothesis_falsified is the valuable stop. The agent set out to prove something and the code said no. That's the most informative outcome available, and it leads the digest. An agent that can't stop this way will instead quietly reshape the problem until its first guess looks right — the most expensive failure mode in agentic coding. runtime_falsified is its sibling: the gates were green and the running app said no. Static reasoning about a runtime failure was independently wrong twice in the reviewed repo's worst incident; only executing the thing settled it.

Every stop is a handoff, not a dead end. Whatever ends a run — a door, a budget, a falsified hypothesis, a dropped connection — the exit path is the same: write the handoff, leave the branch, exit clean.

The gate has tiers, because checking has a price

verify.shRunsWhen
fastlintAfter every unit of work
fullfast + headless specs + a self-test that the gate hook actually firesBefore every commit
smokefull + production build + a generic route-mount check, no copy assertionsAt a checkpoint mid-implement
deepsmoke + the full feature-driving e2e suiteOnce, before handing back

One contract, four costs; the preflight exits non-zero with a reason rather than ever passing silently. smoke and deep both drive the actual production build (what npm run build produces, served by a small static file server written for exactly this) rather than a dev server — a dev server can be a leftover process of unknown provenance still listening from an earlier session, which is the mechanism behind a report that once reached a human as "all tests pass" and was wrong. The two runtime tiers check different things on purpose: smoke is cheap and generic — every route mounts, nothing throws — so it belongs inside the fix loop, where a runtime contradiction can actually be caught and corrected rather than discovered once at the end; deep adds the acceptance-test shape, which is a much narrower regression net (it breaks on any copy change too), so it stays reserved for hand-back. Four things are never trusted on their own: VERIFY: PASS without reading the test diff, status: completed without a matching git diff, a metric that improved after its own config was edited, and "nothing failed" over a list of zero checks.

04 — SKILLS

Alone or in concert, same file

A skill is a markdown file with frontmatter. It works standalone because it heals its own preconditions; it composes because it emits structured output to a shared run directory. No orchestrator to install.

The contract

Self-healing preconditions. Call /implement cold with no brief and it runs /understand first, then continues. Call it inside a flow and the brief already exists, so it skips through. Same prompt, same code path — the only difference is what's already on disk.

Structured emit. Each skill ends by writing one JSON file. That's the entire integration surface: the next skill reads it, the digest aggregates it, you can cat it.

Idempotent and resumable. Re-running with unchanged inputs is a no-op — which is precisely what makes an interrupted run safe to continue rather than restart.

.ai/run/vehicle-models/implement.json — the actual mechanical shape

{
  "skill": "implement",
  "status": "ok",
  "artifacts": ["brief.md", "journal.md"],
  "files_changed": ["src/app/vehicle/vehicle.service.ts", "..."],
  "spent": { "min": 12, "files": 6 }
}

This replaces an earlier, richer example (decisions_needed, learned, next, a token count) that turned out to be the actual reason no emit was ever written for a full phase: those fields need judgment a shell script can't supply, and a script that faked them would be self-report wearing a mechanical costume — the exact failure this file exists to avoid. .ai/harness/emit.sh writes only what git and the filesystem can attest to; a skill's judgment calls belong in the brief and the digest, not in this file. files_changed comes from git diff --name-only plus untracked files, never from the agent's recollection — self-report is not evidence.

Parallelism is git worktrees, not a framework. /diverge spawns three worktrees off one commit, runs a spike in each, and puts the three findings side by side. Nothing to install, works with any agent, and the losers are deleted directories. Worktrees also solve a subtler problem: a second concurrent session once git add-ed an unrelated 645-line file into the reviewed repo's shared working tree, and a pathspec-less commit nearly landed it. Separate trees make that impossible; until then, always commit with an explicit pathspec.

Skills load at session start — a file written mid-session is invisible. The reviewed repo ran a whole phase through a generic fallback agent because the intended agent's file didn't exist when the session began; the one hook keyed on it silently never fired, and nothing said so. Two rules follow: any change to a prompt, command or hook file ends with "restart the session", stated by the skill itself; and a run asserts that each expected hook fired at least once — "nothing failed" over zero firings is a vacuous pass. Built in the v4.2 remediation as .ai/harness/hook-test.sh, wired into verify.sh full: it pipes a crafted payload through the actual hook and checks the exit code for each of fourteen cases, plus a negative control that patches a copy of the hook to disable a real check and confirms the suite goes red for exactly that — the earlier version of this claim had neither a fired-check nor a blocked-correctly check, which is a distinct, sharper vacuous pass than the one this paragraph originally described: the hook can fire and still be wrong about what it blocks. One nuance surfaced building it: whether "restart the session" is even accurate turned out to depend on which file changed — a prompt or command file genuinely needs one, but a .claude/settings.json hook-matcher change took effect immediately, mid-session, no restart required. The two mechanisms load differently; the rule as stated conflated them.
05 — DURABILITY

Survive the kill

Usage limit, dead container, dropped connection, closed laptop. The design assumption is that any run can be terminated between any two steps, without warning, with no chance to summarise.

Three layers, cheapest first

1 · WIP commits. Free, and the strongest recovery you own. The agent commits on its branch after each green step. Git is the ledger; everything else just explains it.

2 · journal.md, append-only. One line per meaningful step, written before the step and amended after. Costs a handful of tokens; turns "what was it doing?" into a fact. Write-ahead matters: the ambiguous case that breaks naive resume is a step that was in flight when the lights went out.

3 · HANDOFF.md. Written for a cold agent with zero context. Fires on every stop condition, and can be written by hand.

The part most designs get wrong

If you hit a usage limit, you cannot call the model to summarise. So the fallback handoff must be generated without an LLM: a Stop hook or shell trap concatenates the journal tail, git status, git diff --stat and the last emit into HANDOFF.md. Cruder than the written version, and entirely sufficient to resume. The good handoff is an optimisation; the mechanical one is the guarantee.

Where a journal isn't worth it

Skip it for read-only exploration and anything under a minute. The rule: journal a step if redoing it would cost more than it costs to record it, or if it changed the working tree. Most reads are free to repeat; no edit ever is.

06 — MEMORY

Five shelves, two of them yours

Automatic capture makes documentation. Curated capture makes a body of work. The bank is the second kind, and it's the only shelf where you decide what goes in.

.ai/run/<slug>/
agent · hours

Brief, journal, emits, digest, handoff, retro. Deleted when the work lands.

.ai/decisions/
agent · permanent

One record per meaningful change: Problem, Root cause, Decision, Why, Trade-off, Concept. Doubles as commit body and PR text.

.ai/bank/
you · permanent

Cards you pointed at. Facts, failures, hunches, quotes. Survives the repo — this is the shelf that becomes a blog post or a change to how you work.

.ai/MODEL.md
you · living

The map of the system. Agents propose diffs; the hook blocks direct writes — enforced, not requested. Kept to two pages, deliberately.

.ai/harness/OWED.md
both · living

What only a human can apply (a door-7 fix), or what a bank card named as its own fix and nothing then built. An agent proposes an entry; a human strikes it once it's actually done — not deleted silently, struck with a pointer to what closed it.

One owner per fact. The shelves earn their keep only if their boundary fits in a sentence each: MODEL.md is how the system is now (present tense, replaceable) · decisions/ is why it changed, dated (past tense, append-only) · a bank card is what it taught that outlives this repo (portable). Conventions belong to CLAUDE.md and are never restated inside .ai/ — a planned conventions.md was deleted mid-build for exactly this reason. And in a repo that already keeps a failure log, /keep appends to that: the harness absorbs existing stores, it does not stand beside them. Parallel stores drift, drift produces no error, and the wrong answer arrives looking healthy.

Capture is one gesture

Bare /keep reads what just happened and proposes two or three candidate cards; you pick one, or type your own sentence. /keep "specs mocking the store hid this for a year" skips straight to the card. Either way it's seconds, and it runs on the small model.

Failed experiments are the point. A dead spike is normally a deleted branch and nothing else — the most expensive knowledge you generate, routinely thrown away. kind: failure cards are the only place a negative result survives, and they're what stops you re-running the same idea in eight months.

Three ways it pays back

Reasoning. /recall <topic> loads matching cards ahead of understand, so a new run starts with what you already concluded instead of rediscovering it. Only headers are scanned until something matches — cheap by construction.

Writing. /draft <tag> collects cards into an outline. Because each card carries a date, a real file reference and the cost of being wrong, the draft has the specifics that make a post worth reading — which is exactly what you can't reconstruct months later.

Process tuning. Cards tagged about: process feed the rule ledger. Three cards describing the same friction become a proposed rule with its evidence attached, rather than a vibe you half-remember.

Kept honest

A bank that only grows is a graveyard. Cards never recalled in six months get proposed for bank/attic/ — moved, never deleted, because a card you ignored for a year is sometimes exactly the one you need at year two.

07 — SPEND

Cheap by construction

Most of the token volume in a loop like this is clerical. Routing it correctly costs nothing and changes the economics more than any prompt tuning.

One honest caveat, updated. The split above was a design intent, not a measurement, for an entire phase — because the emit file every prompt's frontmatter declared was never actually written, by any run, ever. .ai/harness/emit.sh and ledger.sh exist now (v4.2 remediation), and a token count is deliberately not one of the fields either records: it can only come from the agent's own self-report, and a "spend ledger" built partly on self-report would smuggle back in the exact failure mode — an unverifiable number wearing a mechanical costume — this whole page argues against elsewhere. What's measured is minutes and files touched, both git- and clock-derived. The corpus itself is still thin — real for the runs that built this feature, absent for everything before it, since backfilling estimated numbers for already-closed runs would be fabrication, not measurement. If routing turns out not to matter once there's enough data, that's a finding worth a card.

09 — ROLLOUT

Where it stands

Phase 0 and 1 are built, committed, and dogfooded — the scaffold ran as its own first run, brief to decision record. What each phase claims below is what its verification actually showed, not what was intended.

PHASE 0+1✓ built

Doors, digest, journal, durability, bank — built, dogfooded, and delivered a feature

Nine prompts, the seven-door list, four verify.sh tiers, check-citations.sh, the mechanical handoff, budget.mjs live and firing — and, since the v4.2 remediation, actually asserted to fire: hook-test.sh runs a crafted payload through the hook and checks the exit code, with a live negative control that patches a copy of the hook to disable a real check and confirms the suite goes red for it, not just green by default. Proven, not just written: the hook blocked its own author mid-edit on a real MODEL.md crossing; check-citations.sh caught fabricated-looking citations three times now — its own dotfile bug, a citation that drifted onto a blank line after an unrelated edit shifted the file underneath it, and (once bare-path resolution was added) a stale reference to a deleted service that had read as clean for a full phase; and a full feature (vehicle brand/model selection) went brief → failing-first specs → green → verify deep passing with Playwright actually selecting a brand and watching its models appear in a real browser.

One claim in this section was wrong for a while and is worth naming rather than quietly fixing: this paragraph used to say the blast-radius allowlist was "enforced live, not advisory," with its proof being that a run's own state.json records which files it touched, "not self-reported." A later run (ui-shell-redesign) recorded five files touched against an actual thirty-file change — the guard was real, but deleting state.json to get past it and rewriting it by hand had become the routine workaround for a brief needing a mid-run correction, and each deletion silently reset the count to zero. The mechanism looked self-verifying and wasn't. Fixed in the v4.2 remediation: state.json is now genuinely single-writer (the hook blocks every other write to an existing one), the active run's own directory is always in scope so there's no reason left to delete it, and files_touched is derived from git diff on every guarded call rather than accumulated from which tool happened to be used. The claim is true again now — but a claim can look true, on paper, for an entire phase without being checked against what actually happened, and that's the more useful lesson than the fix itself.

DELIVEREDmid-build

The runtime tier, for free

An unrelated Angular 9 → 14 upgrade replaced Karma/Protractor/tslint with Jest/Playwright/ESLint on the host repo's own timeline — and Playwright's dev-server bootstrap made verify deep a genuine runtime oracle without the dedicated session this page originally deferred it to. The lesson isn't "get lucky" — it's that door 7's file list is pinned to specific paths that go stale the moment the toolchain moves, silently, with the old paths simply no longer existing. The retool also surfaced a smaller drift worth naming honestly: config.yml's gate_scope_paths and budget.mjs's hardcoded list now duplicate the same door-7 list from two places, because the hook has no YAML parser and adding one is itself a dependency change. Logged, not fixed — one owner per fact, bent on purpose for a real constraint.

v4.2 REMEDIATION✓ built

10 — RISK

What I'd still watch

Bank hoarding. Capture is so cheap it becomes reflexive, and the signal drowns. The attic sweep helps; the real discipline is that a card must say what it costs you to not know the thing.

Journal drift. A journal that gets written after the fact rather than before is worse than none — it looks authoritative and describes a run that didn't happen. Write-ahead or off, no middle setting.

Confident fiction. More autonomy means more unread text, and unread text is where fabrication hides. file:line — and, since the v4.2 remediation, bare-path — citations everywhere, resolved automatically by check-citations.sh on every run. That script proves a citation resolves, not that it's apt: it prints the cited line's content so a human eye catches a misattribution the exit code can't see. Resolution being automated is what makes the weekly human pass affordable to spend entirely on aptness now, instead of splitting attention between "does this exist" and "is this the right line" — the former is a script's job, the latter still needs a reader.

The default becomes the answer. If every decision ships with a recommendation you'll take it — which is fine and intended, but the ledger has to notice, because a decision you never override should stop being asked.

Branch sprawl. Unattended runs produce branches faster than you review them. One flow in flight at a time until you trust the digests.

Green but never executed — closed. verify deep now boots the app and drives it with Playwright; a real feature (vehicle selection) was verified this way, not just compiled. unverified_at_runtime still exists as a state and still matters for any run that only reaches fast or full — the watch item now is making sure that distinction stays visible rather than reading every green the same way.

The gate's own config. Enforced now (door 7, always on), and self-tested (hook-test.sh asserts it fires and blocks correctly, with a live negative control). The override exists and the failure's signature is a better number — so the residual risk is an override that never made it into a digest. Overrides are grep-able (HARNESS_DOOR_OPEN, and in an environment where that mechanism doesn't reach the hook at all, a prepared patch file in a run directory instead); verify.sh deep now greps for one not named in its run's digest, rather than leaving "check occasionally" as the only defense.
